## 一、设计原则与约束回顾

| 编号 | 规范项 | 本项目执行方式 |
|------|--------|---------------|
| N1 | snake_case 命名 | 所有表名、字段名均使用小写英文 + 下划线 |
| N2 | 主键自增 | 每张表 `id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY` |
| N3 | 无物理外键 | 所有关联用逻辑字段（如 `user_id`、`question_id`），应用层校验完整性 |
| N4 | NOT NULL + 明确默认值 | 必填字段设 `NOT NULL`，时间字段默认 `CURRENT_TIMESTAMP`，状态字段有明确含义的默认值 |
| N5 | UTC 存储 + 展示层转时区 | **例外确认**：学习时间类字段（`answered_at`、`last_login_at` 等）按 K7/K8 决策以 Asia/Shanghai 日界计算，存入时区标记为 CST；系统管理端操作日志统一 CST；密码加密哈希本身不带时区信息 |
| N6 | 状态字段有限集合 | 所有枚举字段附注释说明取值含义 |
| N7 | 禁止拼接多业务值 | JSON 列仅用于真正不可拆分的半结构化数据（选项列表、标签数组、权限码集） |

## 五、枚举值与状态定义

### 5.1 题目类型（`question.type` / `interview_question.difficulty`）

| 值 | 含义 |
|----|------|
| `single_choice` | 单选题 |
| `multiple_choice` | 多选题 |
| `judge` | 判断题 |
| `essay` | 简答题 |

### 5.2 题目难度（`question.difficulty` / `interview_question.difficulty` / `interview_record.difficulty`）

| 值 | 含义 |
|----|------|
| `easy` | 简单 |
| `medium` | 中等 |
| `hard` | 困难 |

### 5.3 题目状态（`question.status`）

| 值 | 含义 | 流转 |
|----|------|------|
| `draft` | 草稿 | 新建后初始状态 |
| `pending_review` | 待审核 | 提交审核后进入 |
| `published` | 已上架 | 审核通过后，学员可见可刷 |
| `offline` | 已下架 | 下架后学员不可见 |
| `rejected` | 已驳回 | 审核不通过，运营重新提交后回到 `pending_review` |

### 5.4 账户状态（`admin_user.status` / `student_account.status`）

| 值 | 含义 |
|----|------|
| `0` | 已禁用 |
| `1` | 已启用（默认） |

### 5.5 菜单类型（`sys_menu.menu_type`）

| 值 | 含义 |
|----|------|
| `1` | 目录（可展开子菜单） |
| `2` | 菜单（最终页面入口） |
| `3` | 按钮（操作权限控制） |

### 5.6 面试题来源（`interview_question.source_type`）

| 值 | 含义 |
|----|------|
| `manual` | 手工录入 |
| `excel_import` | Excel 批量导入 |

### 5.7 练习模式（`practice_session.mode`）

| 值 | 含义 |
|----|------|
| `sequence` | 顺序练习 |
| `random` | 随机练习 |

### 5.8 学科关联类型（`course_subject.is_primary`）

| 值 | 含义 |
|----|------|
| `1` | 主学科 |
| `0` | 关联学科 |

## 六、特殊字段说明

### 6.1 JSON 列的使用场景

| 表 | 字段 | JSON 结构示例 | 理由 |
|----|------|--------------|------|
| `question` | `options` | `[{"label":"A","content":"内容","is_correct":true}, ...]` | 选项数量可变（2~6个）、正确答案不固定 |
| `question` | `tags` | `["Java", "Spring", "微服务"]` | 标签数量可变、非结构化 |
| `interview_question` | `tags` | `["大模型", "Prompt", "RAG"]` | 同 question.tags |
| `sys_role` | `permissions` | `["question:view", "question:add", ...]` | 33项权限点的动态集合，不同角色组合不同 |
| `practice_session` | `answers` | `{"101":{"selected":["A"],"scored":false},"102":{"selected":["B","C"],"score":7,"passed":true}}` | 每次练习的临时进度快照，结构不固定 |

### 6.2 时长字段的存储策略

| 字段 | 类型 | 存储值 | 说明 |
|------|------|--------|------|
| `course.duration` | `VARCHAR(8)` | `"02:30"` | 展示用，直接读取 |
| `course.duration_minutes` | `INT` | `150` | 计算用（总时长统计、课程对比），由 `duration` 转换存入 |
| `interview_record.duration_sec` | `INT` | `847` | 秒为单位，便于排序和求平均 |
| `practice_session.elapsed_seconds` | `INT` | `1234` | 实时计时，session 结束时无需再转换 |

### 6.3 时间字段时区策略

| 字段类别 | 时区 | 说明 |
|----------|------|------|
| 时间戳类（`created_at`、`updated_at`） | UTC | 通用审计字段，UTC 存储，展示层按需转换 |
| 学习行为类（`answered_at`、`last_login_at`、`last_error_at`、`mastered_at`、`started_at`、`completed_at`、`practice_session.updated_at`） | Asia/Shanghai (CST) | 学习天数去重按日界计算；近7天柱状图按 CST 分组 |
| 操作日志（`operation_log.created_at`） | Asia/Shanghai (CST) | 管理端使用，面向国内运营人员 |

> 服务端统一在写入时使用 `LocalDateTime.now(ZoneOffset.ofHours(8))` 或 MySQL `NOW()`（服务器时区设为 CST），避免应用层与时区漂移问题。

### 6.4 逻辑删除策略

除以下两张临时表外，其余业务表均含 `is_deleted TINYINT DEFAULT 0`：

| 表 | 删除策略 | 理由 |
|----|---------|------|
| `answer_record` | **物理删除**（不设 is_deleted） | 答题记录为流水型数据，量大且与学员生命周期绑定，学员注销时级联清理即可 |
| `practice_session` | **物理删除**（不设 is_deleted） | 会话结束后立即删除；超 24h 未使用的过期会话由定时任务清理 |
| `interview_message` | **物理删除**（不设 is_deleted） | 随 interview_record 一起删除；面试报告生成后消息保留至记录删除 |
| `course_subject` | 随 `course` 或 `subject` 逻辑删除时清理 | 无独立查询需求，由应用层维护一致性 |
| `course_route_item` | 随 `route` 逻辑删除时清理 | 同上 |
