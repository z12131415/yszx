## 一、统一响应结构

### 1.1 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | `Integer` | 业务状态码，`0` 表示成功，非 `0` 表示失败 |
| `message` | `String` | 提示信息，成功时固定为 `"success"`，失败时为具体错误描述 |
| `data` | `Object / Array / Null` | 业务数据，无数据时为 `null` |

### 1.2 失败响应

```json
{
  "code": 40001,
  "message": "手机号格式不正确",
  "data": null,
  "fieldErrors": [
    { "field": "phone", "message": "请输入11位手机号码" }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | `Integer` | 业务错误码（见第五节） |
| `message` | `String` | 面向用户的友好提示 |
| `data` | `Any` | 通常为 `null` |
| `fieldErrors` | `Array\<FieldError\>` | 参数校验错误列表，可选；有值时逐项列出字段和原因 |

### 1.3 分页结构

所有列表接口统一返回以下分页包装：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 156,
    "page": 1,
    "pageSize": 20,
    "totalPages": 8
  }
}
```

- `page`：当前页码，从 `1` 开始
- `pageSize`：每页条数，默认 `20`，最大 `100`
- `total`：总记录数
- `totalPages`：总页数 = ceil(total / pageSize)

## 二、通用查询参数约定

所有支持筛选的列表接口均支持以下公共查询参数（GET 请求）：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `page` | Integer | 否 | 1 | 页码，≥ 1 |
| `pageSize` | Integer | 否 | 20 | 每页数量，范围 [1, 100] |
| `sortBy` | String | 否 | — | 排序字段，取决于接口定义 |
| `sortOrder` | String | 否 | `desc` | 排序方向：`asc` / `desc` |

## 三、学员端 API（`/api/portal/`）

> 全部接口需携带有效 `student_token`（HttpOnly Cookie）。未认证请求返回 `HTTP 401`。

### 3.1 M01 — 账户与认证

#### 3.1.1 POST `/api/portal/auth/register`

**用途**：学员注册（手机号 + 密码）

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| `phone` | String | 是 | 11 位数字，符合中国大陆手机号正则 | 唯一标识，同时作登录账号 |
| `email` | String | 否 | 邮箱格式 | 可选，唯一约束 |
| `nickname` | String | 是 | 长度 2~20，不支持纯数字 | 显示昵称 |
| `password` | String | 是 | 8~32 位，含字母+数字 | BCrypt 加密存储 |
| `passwordConfirm` | String | 是 | 与 `password` 相同 | 二次确认 |
| `agreedTerms` | Boolean | 是 | 必须为 `true` | 用户协议勾选 |
| `smsCode` | String | 否 | 6 位数字 | 若注册时使用了验证码则必填 |

**响应**（`code: 0`）：

```json
{ "studentId": 1, "nickname": "张三" }
```

**业务规则**：
- 手机号已注册或格式非法 → `40002`
- 邮箱若填写且已被占用 → `40003`
- 密码强度不足（不含字母或数字）→ `40004`
- 用户名违规（纯数字昵称）→ `40005`

---

#### 3.1.2 POST `/api/portal/auth/login`

**用途**：密码登录

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `phone` | String | 是 | 手机号 |
| `password` | String | 是 | 明文密码 |

**响应**（`code: 0`）：服务端设置 `Set-Cookie: student_token={jwt}`，返回：

```json
{ "userId": 1, "nickname": "张三", "avatarUrl": "https://..." }
```

**业务规则**：
- 账号不存在或密码错误 → `40010`
- 连续输错 5 次锁定账号 5 分钟 → `429` + `LOCKED`
- 账号已禁用 → `40011`

---

#### 3.1.3 POST `/api/portal/auth/login-sms`

**用途**：手机验证码登录

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `phone` | String | 是 | 手机号 |
| `smsCode` | String | 是 | 6 位验证码 |

**响应**同 3.1.2，登录成功后自动补注册缺失字段（nickname 取手机号后四位）。

---

#### 3.1.4 POST `/api/portal/auth/send-code`

**用途**：发送短信验证码（注册 / 找回密码 / 验证码登录共用）

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `phone` | String | 是 | 手机号 |
| `scene` | String | 是 | 场景：`register` / `login_sms` / `forgot_password` |

**响应**（`code: 0`）：

```json
{ "expireSeconds": 60 }
```

**业务规则**：
- 60s 内重复发送 → `429` + "请勿重复获取"
- 单日超过 10 次 → `429` + "今日次数已达上限"
- 手机号格式非法 → `40002`

---

#### 3.1.5 POST `/api/portal/auth/forgot-password`

**用途**：三步式找回密码（验证身份 → 重置密码 → 确认修改）

**步骤一 — 验证身份**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `phone` | String | 是 | 手机号 |
| `smsCode` | String | 是 | 验证码 |

**步骤二 — 重置密码**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `phone` | String | 是 | 手机号 |
| `newPassword` | String | 是 | 新密码（8~32位，含字母+数字） |
| `newPasswordConfirm` | String | 是 | 再次确认 |
| `smsCode` | String | 是 | 验证码（复用步骤一的会话） |

**响应**（两步统一）：

```json
{ "message": "密码重置成功，请使用新密码登录" }
```

---

#### 3.1.6 POST `/api/portal/auth/logout`

**用途**：退出登录（使当前 JWT 加入 Redis 黑名单）

**无请求体**。

**响应**（`code: 0`）：清除 Cookie，返回空 data。

**响应**（`code: 0`）：

```json
{
  "userId": 1,
  "phone": "138****1234",
  "nickname": "张三",
  "gender": "男",
  "avatarUrl": "https://...",
  "status": 1,
  "createdAt": "2026-10-01T08:00:00+08:00"
}
```

### 3.3 M08 — 刷题与练习

#### 3.3.1 POST `/api/portal/practice/start`

**用途**：开启一次练习会话

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `catalogId` | Long | 是 | 阶段 ID |
| `mode` | String | 是 | `sequence` / `random` |
| `questionIds` | Array\<Long\> | 否 | 指定题目ID数组；不传则使用该阶段所有上架题 |

**响应**（`code: 0`）：

```json
{
  "sessionId": "ps_abc123",
  "totalQuestions": 20,
  "currentIndex": 0,
  "questions": [
    {
      "id": 101,
      "content": "...",
      "type": "single_choice",
      "options": [...],
      "index": 0
    }
  ]
}
```

> **注意**：会话首次创建时将题目快照写入 `practice_session.answers`，每次刷新页面前端应从服务端重新拉取而非仅靠 sessionStorage。

**业务规则**：
- 阶段不存在或该阶段无上架题目 → `40401`
- 同一用户同一时段（24h 内）已有未结束会话 → 自动续接原 sessionId，返回 `"resumed": true`

---

#### 3.3.2 PUT `/api/portal/practice/:sessionId/answer`

**用途**：提交选择题答案

**路径参数**：`sessionId`（String）

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `questionId` | Long | 是 | 题目ID |
| `selectedOptions` | Array\<String\> | 是 | 所选选项 label，如 `["A","C"]` |

**响应**（`code: 0`）：

```json
{
  "questionId": 101,
  "selectedOptions": ["A"],
  "isCorrect": true,
  "score": 10,
  "passStatus": 1,
  "hasNext": true,
  "nextIndex": 1,
  "summary": { "answered": 3, "correct": 2, "elapsedSeconds": 45 }
}
```

---

#### 3.3.3 POST `/api/portal/practice/:sessionId/score`

**用途**：AI 批改简答题并提交评分结果

**路径参数**：`sessionId`（String）

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `questionId` | Long | 是 | 题目ID |
| `answer` | String | 是 | 学生作答文本，不限长度下限 |

**响应**（`code: 0`）：

```json
{
  "questionId": 101,
  "score": 7.0,
  "passStatus": 1,
  "aiComment": "回答基本正确，但缺少对...的阐述...",
  "keyPoints": ["IOC原理", "依赖注入"],
  "referenceAnswer": "参考要点：①... ②...",
  "isCorrect": true,
  "hasNext": true
}
```

**业务规则**：
- AI 服务超时（30s）→ 暂存答案并标记 `score: null`，返回 `"deferred": true`，前端提示"稍后可查看评分"
- 答案为空或过短 → `40006`

---

### 3.4 M09 — 错题管理

#### 3.4.1 GET `/api/portal/wrong-questions`

**用途**：错题本列表（待复习 + 已掌握，可按状态过滤）

**查询参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `status` | String | 否 | `all` / `pending` / `mastered`，默认 `pending` |
| `difficulty` | String | 否 | 按难度过滤 |
| `tag` | String | 否 | 按标签过滤 |
| `sortBy` | String | 否 | `error_count` / `last_error_at` / `correct_rate`，默认 `error_count desc` |

**响应**（`code: 0`）：分页，每项包含题目摘要、错误次数、纠正进度、是否已掌握。

```json
{
  "items": [
    {
      "id": 201,
      "content": "MyBatis 一级缓存的作用域是？",
      "type": "single_choice",
      "difficulty": "medium",
      "tags": ["MyBatis"],
      "errorCount": 3,
      "correctCount": 1,
      "isMastered": false,
      "lastErrorAt": "2026-11-08T14:23:00+08:00"
    }
  ],
  "total": 47,
  "stats": { "totalCount": 47, "pendingCount": 32, "masteredCount": 15, "masterRate": 0.32 }
}
```

---

#### 3.4.2 POST `/api/portal/wrong-questions/review`

**用途**：错题重做模式提交答案

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `questionId` | Long | 是 | 题目ID（必须在当前用户错题本中） |
| `selectedOptions` | Array\<String\> | 选择题必填 | 所选选项 |
| `answer` | String | 简答题必填 | 学生作答 |

**响应**（`code: 0`）：

```json
{
  "questionId": 201,
  "isCorrect": true,
  "correctCountIncrement": 1,
  "isNewMastered": false,
  "remainingWrongCount": 31
}
```

**业务规则**：
- 连续答对 3 次 → `isNewMastered: true`，自动从待复习列表移除
- questionId 不在本题用户的错题本中 → `40402`

#### 3.4.4 DELETE `/api/portal/wrong-questions/batch`

### 3.6 M10 — AI 模拟面试

#### 3.6.1 POST `/api/portal/interviews/config`

**用途**：创建面试会话（预校验配额后再启动）

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `direction` | String | 是 | 技术方向（8选1） |
| `difficulty` | String | 是 | `easy` / `medium` / `hard` |
| `questionCount` | Integer | 是 | 题量：`3` / `5` / `8` / `10` / `15` |
| `timeLimitMin` | Integer | 否 | 时间限制（分钟），默认 5 |

**响应**（`code: 0`）：

```json
{
  "interviewId": "iv_xyz789",
  "direction": "backend",
  "difficulty": "medium",
  "questionCount": 5,
  "timeLimitSec": 300,
  "dailyQuotaRemaining": 4,
  "questions": [
    { "id": 501, "content": "...", "topic": "JVM", "order": 1 }
  ]
}
```

**业务规则**：
- 今日配额用完（每日 5 次）→ `42901` + "今日面试次数已达上限，明日 0 点重置"
- 同一用户存在活跃面试会话（未完成）→ `40901` + "请完成当前面试"

---

#### 3.6.2 POST `/api/portal/interviews/:interviewId/answer`

**用途**：提交一道面试题答案，触发 AI 实时评分

**请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `questionId` | Long | 是 | 当前题目ID |
| `answer` | String | 是 | 学生作答，长度 20~3000 |
| `durationSec` | Integer | 否 | 本题用时（秒），用于计算总时长 |

**响应**（`code: 0`）：

```json
{
  "questionId": 501,
  "score": 7.5,
  "comment": "回答结构清晰，但对 GC 算法细节了解不足...",
  "keyPoints": ["GC算法", "内存模型"],
  "missingPoints": ["CMS收集器特点"],
  "isLastQuestion": false,
  "currentIndex": 2,
  "totalQuestions": 5,
  "cumulativeScore": 31.0,
  "avgScore": 6.2
}
```

**业务规则**：
- AI 调用超时 → 降级策略返回 `"deferred": true`，分数后续异步补齐
- 题目不属于本场面试 → `40007`

---

## 六、权限控制设计

### 6.1 9 组 33 项权限码完整清单

| 组编号 | 组名 | 权限码列表 |
|--------|------|-----------|
| G1 | 仪表盘 | `dashboard:view` |
| G2 | 学科管理 | `subject:view, subject:add, subject:edit, subject:delete` |
| G3 | 课程管理 | `course:view, course:add, course:edit, course:delete, course:import, course:export` |
| G4 | 题库管理 | `question:view, question:add, question:edit, question:delete, question:import, question:export` |
| G5 | 面试题库 | `interview_question:view, interview_question:add, interview_question:edit, interview_question:delete, interview_question:import` |
| G6 | 题库审核 | `question:review` |
| G7 | 路线管理 | `route:view, route:add, route:edit, route:delete` |
| G8 | 学员管理 | `student:view, student:edit, student:delete, student:export` |
| G9 | 系统管理 | `user:view, user:add, user:edit, user:delete, role:view, role:add, role:edit, role:delete, log:view, log:export, log:clear, setting:edit` |

### 6.2 角色权限分配

| 角色 | 授权组 |
|------|--------|
| 超级管理员 (`super_admin`) | G1~G9 全部（等效通配符 `*`） |
| 内容审核 (`content_reviewer`) | G1, G2(view only), G4(view), G6 |
| 运营人员 (`operator`) | G1, G2(增删改), G3, G4(增删改+导入导出), G5(编删+导入), G7, G8, 不含 G6/G9 |

### 6.3 实现方式

- 网关层：`AdminJwtFilter` 解析 JWT 中的 `permissions` 字段至 `SecurityContext`
- 控制层：关键写操作使用 `@PreAuthorize("hasPermission('question', 'add')")` 注解驱动
- 菜单渲染：前端根据 `permissions` 列表动态过滤菜单项和按钮
- 接口粒度：按钮级权限通过 `permission_code` 字段关联 `sys_menu`，前端按需隐藏/显示

## 七、全局异常处理

采用 `@ControllerAdvice` 全局异常处理器，覆盖以下场景：

| 异常类型 | HTTP 状态 | 业务错误码 | message 示例 |
|---------|----------|-----------|-------------|

| `BindException` | 400 | 同上 | 查询参数绑定失败 |
| `AccessDeniedException` | 403 | `40301` | 无权执行此操作 |

### 9.3 接口与架构设计的一致性

- ✅ 学员端 `/api/portal/**` 与管理端 `/api/admin/**` 路径前缀分离，无交叉
- ✅ 两端 JWT 独立签发（不同 secret、不同 cookie name、不同 blacklist key）
- ✅ AI 评分通过 `AiScoringService` 封装，接口层不直连外部 LLM
- ✅ Excel 导入接口均为 `multipart/form-data`，支持流式读取
- ✅ 文件上传走本地+OSS双写抽象层 `FileService`
- ✅ 频控通过 `RateLimitAspect` AOP 切面统一拦截，不在业务代码中硬编码
