## 一、项目概述

**产品定位**：AI 赋能的智能面试训练平台。  
**核心闭环**：学科 → 阶段 → 题目 / 课程 / 路线；刷题 → 错题 → AI 面试 → 报告 → 补强。  
**部署形态**：学员端（portal）与管理端（admin）独立部署，账号体系独立，需分别登录。

## 二、主要功能梳理

### 2.1 学员端（Portal）

| 子模块 | 页面 | 核心功能简述 |
|--------|------|-------------|
| **门户与引导** | 首页 | Hero 首屏（数据统计）、快速开始入口、核心功能卡、学习统计、近 7 天练习柱状图、热门阶段、AI 面试介绍、页脚链接、新手引导三步蒙层 |
| **账号体系** | 登录 / 注册 / 找回密码 | 双方式登录（密码 + 手机验证码）、注册含密码强度检测与协议勾选、三步式找回密码；第三方登录入口（微信/QQ/GitHub）保留位置；安全频控（登录锁、验证码频控、接口限流） |
| **个人中心** | profile | 用户卡片（头像、昵称、角色标签、做题/面试/错题统计）、基本信息编辑（头像上传、用户名、邮箱、性别）、只读脱敏手机号 |
| **题库中心** | questions | 三级浏览（学科 → 阶段 → 题目），左右分栏；题型/难度/关键词筛选；题目卡展示（正确答案率、做过人数、标签）；「查看解析」和「开始练习」双入口 |
| **刷题练习** | practice | 模式选择弹窗（顺序 / 随机）；左侧面板（进度条、计时器、答题卡）；答题区（选择题多选互斥、简答题 AI 批改动画 + 评分卡）；答案解析展示；快捷键支持（←→Enter?）；断点续练（sessionStorage 持久化） |
| **错题本** | wrong-book | 四张统计卡（总数/待复习/已掌握/掌握率）+ Top3 高频错题；浏览模式（错题卡片、筛选排序、批量操作）；重做模式（逐题练习、连续答对 3 次自动标记掌握） |
| **学习路线** | routes | 学科卡片选择（一排 5 个，显示路线数量）→ 路线 Tab 切换（含进度）→ 路线头部信息（课程数/时长/进度条）→ 有序课程列表（封面/BV号/时长/去B站学习/标记已学完） |
| **AI 模拟面试** | ai-config / ai-interview / interview-report / interview-history | 配置页（8 技术方向 × 3 难度 × 5 题量 × 固定 5 分钟）+ 每日 5 次配额；面试对话页（文本/语音输入、AI 朗读、实时评分侧边栏、网络状态检测）；报告页（综合环形图、6 维能力分析、优缺点、改进建议、能力提升卡）；历史记录页（统计 + 分页列表） |

### 4.1 模块依赖关系

          │                                       │

      └──路由──► 题目在学科下的分布（看板图表）

### 4.2 核心业务流程

#### 流程 A：学员刷题完整链路

```
[学员] 首页/导航 ──► 题库中心(M04)
                     │
                     ├── 选择学科 → 选择阶段 → 浏览题目列表
                     │
                     └── 「开始练习」→ 模式选择弹窗(M08)
                                          │
                                          ├── 顺序练习：按题库顺序逐题作答
                                          └── 随机练习：Fisher-Yates 洗牌后作答
                                               │
                                               ├── 选择题：选中选项 → Enter 提交 → 即时判定 ✓/✗
                                               └── 简答题：输入文本 → 提交 → AI 评分动画 → 分数卡(x/10)
                                                          │
                                                          ├── ≥6分 → 通过 ✓
                                                          └── <6分 → 未通过，显示参考答案
                                                               │
                                                        [继续/结束练习]
                                                               │
                                                        结果写入答题记录
                                                               │
                                                         答错 → 自动入 M09 错题本
```

#### 流程 B：AI 面试完整链路

```
[学员] 首页/AI面试导航 ──► 面试配置页(M10)
                             │
                             ├── 选择技术方向（8选1）
                             ├── 选择难度（简单/中等/困难）
                             ├── 选择题量（3/5/8/10/15题）
                             └── 系统校验：今日配额剩余 > 0？否 → 提示「今日额度已用完，明日0点重置」
                                    │
                                    ▼
                            进入面试对话页
                                    │
                                    ├── AI 逐题提问（文本气泡）
                                    ├── 学员作答（文本输入 / 语音识别）
                                    ├── 每题提交后：
                                    │     1. 显示「AI正在分析...」
                                    │     2. AI 评分（0-10分，配色分级）
                                    │     3. 更新侧边栏得分列表
                                    │     4. 进入下一题
                                    └── 全部完成后 → AI 结束语 + 「是否查看面试报告？」
                                              │
                                              ▼
                                        报告生成页(M10)
                                              │
                                              ├── 综合评分环形图
                                              ├── 六维度能力分析卡
                                              ├── 优点列表 / 待提升列表
                                              ├── 改进建议编号列表
                                              └── 能力提升建议卡（推荐题目/课程/再次面试）
                                                       │
                                               [再来一次 / 查看历史 / 返回首页]
                                                       │
                                                  记录写入 M10 历史
```

#### 流程 C：错题本闭环

```
[M08刷题] 答错题目 ──自动写入──► M09错题本
                                              │
                                              ├── 浏览模式：查看错题卡片（错误等级/纠正进度/你的答案 vs 正确答案）
                                              │           ├── 标记已掌握 → 置灰移除
                                              │           └── 批量操作（标记掌握/移除）
                                              │
                                              └── 重做模式：逐题练习
                                                              │
                                                              ├── 答对1次 → 纠正次数+1
                                                              └── 累计答对3次 → 自动标记已掌握 → 移出待复习
                                                                              │
                                                                       仍薄弱？→ 面试报告「推荐题目」补强
```

#### 流程 D：管理端内容生产链路

```
[M03学科管理] 新增学科 + 阶段
        │
        ▼
[M06课程管理] 新增/导入B站课程（含多学科关联）
        │
        ▼
[M04题库管理] 新增/导入题目（关联阶段 → 触发审核流）
        │
        │  草稿 → 提交审核 → 待审核
        │                ├── 通过 → 已上架 → 学员可见可刷
        │                └── 驳回 → 已驳回 → 运营重新提交
        │
        ▼
[M07学习路线] 从课程库选取课程编排学习顺序，发布为路线
        │
        ▼
[学员端] 路线页面读取 → 展示课程清单 → 学员完成标记 → 同步进度
```

## 七、尚不明确 / 需要进一步确认的问题

> 以下问题依据现有需求和原型提取，按影响程度排序。每个问题附"为什么问"和"对哪些决策有影响"。

### Q1：简答题 AI 评分的技术实现方案 ✅ 已确认
**结论**：对接大模型 API（如 Claude/OpenAI），输入题干 + 参考答案 + 学生作答，返回分数 + 评语。
**为什么问**：影响后端架构选型（是否需要独立的 AI 服务层/向量库）。  
**对哪些决策有影响**：后端需引入 AI 服务层；面试环节与答题批改共用同一 LLM 调用链路，技术栈可复用。

---

### Q2：学员端与管理端的部署架构 ✅ 已确认
**结论**：同一域名下 `/portal/` 和 `/admin/` 路径前缀区分，前端各自独立工程构建，后端提供统一 API 命名空间。  
**为什么问**：影响前端工程结构及后端通信模式（CORS vs 独立域名）。  
**对哪些决策有影响**：前端为两个独立 SPA/SSR 工程但同域部署；后端无需 CORS 跨域处理，认证体系可在同一套 Token 机制下扩展角色维度。

### Q3：AI 面试中「技术分析」的实现层级 ✅ 已确认
**结论**：每题交互时即时调用 AI 评分 + 结尾汇总时再生成完整报告（多次短耗时调用）。  
**为什么问**：影响面试接口的响应模式和基础设施成本。  
**对哪些决策有影响**：面试接口需支持逐题流式/异步评分；报告生成在面试结束时基于全部已评分数据集中调用一次；整体体验为实时反馈 + 高质量终报告。

### Q4：B站课程的 BV 号唯一性范围 ✅ 已确认
**结论**：整库唯一（整个平台不允许重复）。  
**为什么问**：影响数据库唯一索引设计和导入冲突处理逻辑。  
**对哪些决策有影响**：`course.bv_id` 字段设置全局 UNIQUE 约束；导入时按 BV 号匹配即判断全库是否存在。

### Q5：学员学习进度的数据来源精度 ✅ 已确认
**结论**："连续学习天数"以任意作答记录计为有效学习日；"今日练习量"统计当日实际答题总数（去重计数）。  
**为什么问**：影响"连续学习天数""今日练习量"等展示的统计口径和服务端压力。  
**对哪些决策有影响**：学习天数按 Asia/Shanghai 日界聚合作答时间戳去重；每日练习量为 `answer_record` 表当日条目数。

### Q8：面试配额重置的精确时点 ✅ 已确认

**对哪些决策有影响**：定时任务在 CST 0:00 触发，服务端日志和时间记录均以北京时间展示给学员。
